# Приложение в трее (`app/`)

Rust, один exe без рантаймов ([ADR 0001](adr/0001-rust.md)). Требования — [requirements.md](requirements.md), поставка —
[ADR 0004](adr/0004-delivery-github-releases.md).

## Вход логином AD (v0.3)
Окно → «Подключение» → «Вход логином AD»: логин и пароль, «Проверить и сохранить». Приложение пробует войти в Jira,
Confluence и SVN и показывает результат по каждому; хоть один принял — пароль уходит в Диспетчер учётных данных
Windows (`DominiVPNMonitor/ad`), и дальше все пробы идут с ним. «Выйти» удаляет его. Первый запуск после установки
сразу открывает эту вкладку. GitLab — токеном `read_api` по паролю AD, когда в настройках задан `gitlab_oauth`
(Application ID приложения GitLab); пока его нет — `GITLAB_TOKEN` в `secrets.env`. Решение — ADR 0006.

## Окно (v0.2)
Двойной клик по иконке или меню → «Открыть окно» открывает в браузере `http://127.0.0.1:5151/` (порт может быть до
5160). Вкладки:
- **Обзор** — оценка VPN и срез по целям; «24 часа / 7 дней»; полосы «где были проблемы» (VPN, задержка, скорость
  до офиса, интернет — окна по 10 минут, за неделю — по часам); графики оценки, задержки, скорости (SVN, GitLab) и
  интернета с порогами и полосами «VPN не включён»; инциденты — когда было «плохо».
- **Подключение** — диагностика подключения по кнопке, адаптеры, прокси, какие секреты заданы, автозапуск, пороги,
  «Проверить обновление».
- **Лог** — хвост лога.

Тот же API — для скриптов и агентов: `http://127.0.0.1:5151/api/help`.

## Что умеет v0.1
- **Режим установки** (двойной клик): закрывает запущенную копию, ставит себя в папку установки
  `%LOCALAPPDATA%\DominiVPNMonitor\vpn-monitor-<версия>.exe`, кладёт рядом `settings.json` и шаблон `secrets.env`,
  включает автозапуск (`HKCU\…\Run`), запускает режим трея. Если секретов нет — открывает `secrets.env` в Блокноте.
  Логин AD пока не спрашивается.
- **Режим трея** (`--tray`): светофор, проверки раз в 3 минуты при зелёном и раз в минуту при жёлтом и красном, левый
  клик — проверка сейчас (во время проверки клики игнорируются).
- **Цели**: Confluence и Jira (v0.3) — светофор; SVN (лёгкий файл каждую проверку, большой — раз в 30 минут) и GitLab
  (`probe/sample_1mb.bin`) — скорость; интернет (`proof.ovh.net`, до 8 с) — раз в 15 минут.
- **Оценка VPN** 01–99 — среднее геометрическое задержки, скорости и стабильности (плохой компонент роняет оценку);
  цвет — по порогам из настроек. Стабильность считается с момента включения VPN (см. `GLOSSARY.md`), поэтому
  выключенный VPN не портит оценку после включения. Задержка и скорость в оценке — медиана последних 5 проверок,
  поэтому один выброс не роняет светофор (в меню — последние значения). Неудачная полная проба повторяется в следующую проверку. «!» — Confluence не отвечает (VPN не включён). Полоски — слабый интернет.
- **Обновление**: при старте (через 10 с) и раз в 5 минут читает `latest.version`; не совпадает со своей версией —
  качает exe и настройки этой версии, сверяет SHA-256, переписывает автозапуск, перезапускается.
- **`--check`** — одна проверка с выводом в консоль и в лог, без трея.

Ещё нет (следующие этапы): «Без ВПН», клиент и профиль VPN, город, отправка метрик в
Prometheus и недельный архив, «Собрать контекст», переезд папки установки, подпись кода.

## Как тестировать
1. Скачать `vpn-monitor.exe` из последнего релиза
   (<https://github.com/dominigamesru/vpn-monitor/releases>) или из артефактов прогона CI нужной ветки.
2. Двойной клик → сообщение «установлен», откроется `secrets.env`. Вписать креды (можно вставить свой `.env`
   целиком — имена ключей те же), сохранить.
3. Левый клик по иконке — проверка. Правый клик — меню со срезом.
4. Что-то не так — меню → «Открыть лог» и прислать `vpn-monitor.log` (секретов в нём нет).

Быстрая проверка без трея — из консоли в папке установки:
```text
cd %LOCALAPPDATA%\DominiVPNMonitor
vpn-monitor-0.1.0.exe --check
```

## Папка установки
| Файл | Что |
|---|---|
| `vpn-monitor-<версия>.exe` | сам exe; старые версии удаляются при старте |
| `settings.json` | настройки этой версии (из релиза; правка руками доживёт до следующего обновления) |
| `secrets.env` | для особых случаев (свои токены, отладка); обычно пуст — вход логином AD хранится в Диспетчере учётных данных |
| `vpn-monitor.log`, `.log.1` | лог, ротация на 5 МБ |
| `metrics_1d.json`, `metrics_7d.json` | метрики (v0.2): одна запись — одна проверка; сутки и сегодня + 7 полных дней (R5.3) |

## Лог
Строка: `время уровень [модуль] сообщение`. Модули: `start` (версия, ОС, папка, откуда настройки, какие секреты
заданы — без значений, прокси), `check` (начало проверки), `probe` (по пробе: хост, DNS→IP, задержка TCP, код HTTP,
скачано, скорость, причина ошибки), `score` (итог и компоненты оценки), `update` (каждый шаг обновления), `tray`,
`install`, `panic` (падение со стеком).

## Релиз
1. Поднять `version` в `app/Cargo.toml` в ветке, pull request, слить в `main` (сливает пользователь).
2. Workflow `release` видит новую версию: тесты, сборка, GitHub Release `vX.Y.Z` с тегом на этот коммит
   (`vpn-monitor.exe`, `settings.json` с SHA-256 exe, `SHA256SUMS`), затем `latest.version := X.Y.Z`. Если `vX.Y.Z`
   уже есть — ничего не делает. Можно и вручную: Actions → `release` → Run workflow, или тег `vX.Y.Z`.
3. Откат — Actions → `promote` → старая версия. Установленные копии перейдут на неё за ~5 минут.

Настройки едут с релизом: поменять цели или пороги — значит выпустить новую версию.
