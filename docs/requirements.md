# Требования (черновик, идёт /grill-with-docs)

Источник — слова заказчика 2026-10-31. Открытые вопросы — в конце; решённое переезжает в текст требований, термины — в
[GLOSSARY.md](../GLOSSARY.md), решения, которые трудно отменить, — в [adr/](adr/).

## 1. Платформа и поставка
- R1.1 Сначала Windows; потом macOS и Linux — язык и библиотеки не должны этому мешать.
- R1.2 Самодостаточно: один исполняемый файл без рантаймов. Язык — **Rust** ([ADR 0001](adr/0001-rust.md)).
- R1.3 Двойной клик по exe — **режим установки**: открыть окно на вкладке входа, где сотрудник вводит логин и пароль
  AD с проверкой на сервисах (v0.3, ADR 0006),
  вычистить хвосты прошлых установок, скопировать себя в папку установки (пользовательское пространство, без прав
  администратора), прописать автозапуск, запустить режим трея, выйти.
- R1.4 Флаг `--tray` — **режим трея**: живёт только в трее, окон нет.
- R1.5 Свежая ручная скачка и запуск чинят любую сбитую установку (тот же режим установки).
- R1.6 Подпись кода: сертификат у компании есть; первая версия — без подписи, подпись — вместе с автосборкой.

## 2. Поставка и обновление ([ADR 0004](adr/0004-delivery-github-releases.md))
- R2.1 Релизы — GitHub Releases публичного репо `dominigamesru/vpn-monitor`: `vX.Y.Z` — exe, настройки этой версии,
  `sha256` (до 0.5.4 — `SHA256SUMS`); `latest` — только `latest.version`. Собирает и публикует CI (GitHub Actions), релиз не меняется.
- R2.2 Раз в 5 минут и при старте приложение читает `latest.version`; не совпадает со своей версией (новее или старше)
  — качает exe и настройки этой версии в папку установки, сверяет SHA-256, переписывает автозапуск, перезапускается.
- R2.3 Откат — записать старую версию в `latest.version` (workflow `promote`), без пересборки.
- R2.4 В настройках — путь к папке установки. Поменяли — при следующем старте переезд, старая папка вычищается.
- R2.5 Секретов в настройках нет. Креды целей — логин и пароль AD в Диспетчере учётных данных Windows (ADR 0006); для
  особых случаев — `secrets.env` в папке установки или переменные окружения (порядок: окружение → `secrets.env` → AD).
- R2.6 Лог `vpn-monitor.log` в папке установки: каждая проба (адрес, код ответа, задержка, скорость, ошибка),
  обновление по шагам, старт и настройки — чтобы по логу понять, что пошло не так. Секреты не пишутся.

## 3. Проверки
- R3.1 Цели и роль каждой:
  - **светофор** считается по **Confluence и Jira** (Jira — `https://jira.corp.dominigames.com/`, проба —
    `/rest/api/2/myself`; вход — логином AD);
  - **GitLab и SVN** — метрики скорости: скачивание пробного файла (GitLab — `probe/sample_1mb.bin` этого репо, 1 МБ
    случайных байт; SVN — путь даст заказчик). Пути, размеры и креды — в настройках;
  - список расширяемый (дальше — SSH, который может идти через VPN).
- R3.2 Проба: задержка (установка соединения) + скачивание. Полная проба (поток 10–20 с) — реже, интервал в настройках.
- R3.3 Цель, трафик к которой идёт мимо VPN, мерится как есть, с пометкой **«Без ВПН»** (сейчас в Happ так идёт GitLab).
- R3.4 Расписание: раз в 3 минуты, если светофор зелёный; раз в минуту — жёлтый или красный.
- R3.5 **Интернет** мерится отдельно, для сравнения, со своим интервалом (уважать рейт-лимиты сервиса).
- R3.6 Клиенты VPN — расширяемо: Happ и OpenVPN Connect сейчас, OpenVPN GUI потом. Определение: маршрут до цели →
  адаптер → клиент (по правилам «адаптер / процесс → клиент» из настроек) → профиль (модуль чтения на клиента).
  Tailscale, WSL и т. п. отсеиваются.
- R3.7 Пороги — в настройках. Старт: задержка < 500 мс, скорость и стабильность — значения по умолчанию в настройках.
- R3.8 (v0.4) Между абсолютными порогами оценка — относительно **нормы** сотрудника (медианы за 7 дней); в окне —
  вклад каждого компонента словами.

## 4. Трей
- R4.1 Основа иконки — `https://dominigames.com/favicon.ico` (одна картинка 60×57, масштабируется). Поверх — знак,
  **цвет знака** = цвет светофора:
  - **оценка VPN** двузначным числом `01`–`99`: взвешенная — плохой любой из компонентов (задержка, скорость,
    стабильность) роняет оценку; отражает удобство работы через VPN;
  - **интернет слабый** — вместо числа полоски как у Wi‑Fi: точка / точка + полукруг / два полукруга; если скорость
    интернета выше порога + 8 Мбит/с — снова число;
  - **VPN не включён** — красный «!»;
  - **идёт проверка** (по клику или фоновая) — значок обновления, клики игнорируются.
- R4.2 Левый клик — проверка сейчас.
- R4.3 Правый клик — меню:
  - «Domini VPN <Город>» — город, где физически находится сотрудник (по IP);
  - клиент и профиль VPN;
  - скорость, стабильность, задержка — текущее значение и дата последнего обновления (графики — позже);
  - интернет — отдельной строкой; если тупит базовый интернет, это должно быть видно;
  - цели «Без ВПН» — с пометкой;
  - «Собрать контекст» — когда не найден ни один совместимый клиент VPN (см. R6);
  - «Открыть окно» (R8), галочка «Автозапуск», «Выйти» (без вопросов).
- R4.4 Двойной клик — открыть окно (R8).

## 5. Метрики ([ADR 0002](adr/0002-metrics-log-and-replay.md))
- R5.1 Метрики пишутся в файлы папки установки и в Prometheus (remote write) по принципу логгера: Prometheus доступен
  только через VPN; запоминается время последней успешной отправки, недошедшее досылается с исходным временем.
- R5.2 Папка установки: `exe`, `json` (копия настроек), `metrics_1d.json`, `metrics_7d.json`,
  `archive/metrics_yyyymmdd-yyyymmdd.zip` (внутри один json с тем же именем — метрики недели).
- R5.3 `metrics_1d.json` — календарные сутки (с 00:00 местного времени); `metrics_7d.json` — текущий день и 7 полных
  дней до него; архив — по неделям.
- R5.4 Каждая запись в Prometheus несёт метки: город, сетевое имя компьютера, логин AD, клиент и профиль VPN. IP не
  нужен. В файлах метрик то же — один раз, в шапке метаданных файла.

## 6. Контекст для поддержки
- R6.1 Не найден ни один совместимый клиент VPN — в меню кнопка «Собрать контекст»: HTML-отчёт о машине и открыть
  `https://jira.corp.dominigames.com/servicedesk/customer/portal/1/create/23` со ссылкой на отчёт.
- R6.2 В отчёте: ОС, версия и сборка, хотфиксы, язык системы и раскладки, сетевые адаптеры (имя, описание, драйвер,
  статус), маршруты до целей, DNS-ответы для целей, запущенные процессы и службы, похожие на VPN, установленное ПО с
  «vpn» и т. п. в имени, папки конфигов известных клиентов (только список файлов, без содержимого — там секреты),
  прокси системы, версия приложения, логин AD, город.

## 7. API (режим для хардкора)
- R7.1 HTTP API на `127.0.0.1:5151` поднимается всегда (окно работает через него, ADR 0005); занят — следующий, до 10
  попыток. Только с этой машины; меняющие запросы — с заголовком `X-VPN-Monitor: 1`.
- R7.2 Не поднялся — приложение работает дальше, но ошибка видна (раз флаг дан, пользователь ждёт API).
- R7.3 Эндпоинты: текущее состояние; запустить проверку; запустить обновление; история качества — средние по часам за
  сутки и по дням за неделю (точная форма — после раунда вопросов).
- R7.4 `GET /api/help` — инструкция для ИИ: как интегрироваться, готовый скилл для харнеса или агента (смотреть
  состояние, запускать проверку и обновление, смотреть историю).

## 8. Окно (v0.2, ADR 0005)
- R8.1 Окно — страница в браузере от локального API, встроенная в exe, без внешних ресурсов. Вкладки: «Обзор»,
  «Подключение», «Лог».
- R8.2 «Обзор»: срез (оценка VPN, задержка, скорость, интернет, стабильность, цели), период «24 часа / 7 дней», полосы
  «где были проблемы» (VPN, задержка, скорость, интернет), графики с общей осью времени и порогами, список инцидентов.
- R8.3 «Подключение»: диагностика подключения по каждой цели (DNS, подставной адрес, маршрут через адаптер, TCP, HTTP,
  кто вошёл, подсказка), сетевые адаптеры, прокси, какие секреты заданы (без значений), автозапуск, пороги, обновление.
- R8.4 «Лог»: хвост лога с автообновлением.

## 9. Вход логином AD (v0.3, ADR 0006)
- R9.1 Вкладка «Подключение» → «Вход логином AD»: логин и пароль, «Проверить и сохранить». Проверка — вход в Jira,
  Confluence и SVN; результат по каждому сервису. Хоть один принял — сохранить; не ответил ни один — «включите VPN»,
  ничего не сохранять.
- R9.2 После входа — «Вошли как …», «Сменить», «Выйти» (удаляет пароль и токен GitLab).
- R9.3 GitLab — OAuth-токен `read_api` по паролю AD, если в настройках задан `gitlab_oauth` (Application ID); иначе
  `GITLAB_TOKEN`.
- R9.4 Не вошли — на «Обзоре» плашка «Войти»; первый запуск после установки сразу открывает вкладку входа.

## Факты окружения (машина разработчика, 2026-10-31)
- Happ (FlyFrogLLC): процессы `Happ.exe`, `happd`, `sing-box`, `xray`; адаптер `happ-tun` (sing-tun). Раздельное
  туннелирование: SVN идёт через `happ-tun` (DNS отдаёт подставной адрес `1.2.3.4`), GitLab (`185.144.63.23`) — мимо VPN,
  через Wi‑Fi. Конфиг — `%LOCALAPPDATA%\Happ\config.json`.
- OpenVPN Connect: `OpenVPNConnect.exe`, служба `agent_ovpnconnect`; адаптеры `TAP-Windows Adapter V9 for OpenVPN
  Connect`, `OpenVPN Data Channel Offload`; профили — `%APPDATA%\OpenVPN Connect\profiles`, `config.json` рядом.
- OpenVPN GUI: конфиги — `%USERPROFILE%\OpenVPN\config`.
- Ещё туннели: Tailscale, WSL — не VPN в офис.
- Машина не в домене (WORKGROUP, локальный пользователь) — логин AD из Windows не взять, только спросить.
- `yandex.ru/internet/api/v0/ip` и `ipv4-internet.yandex.net/api/v0/ip` отвечают `"127.0.0.1"` (трафик через прокси
  Happ?); эндпоинта города нет (404) — для города и замера интернета это API ненадёжно.
- Фавикон dominigames.com — ICO, одна картинка 60×57, 32 бит.
