# net_speed.py — замер канала до GitLab и SVN (через VPN) и до интернета

Утилита отвечает на вопрос «почему всё качается медленно»: виноват канал/VPN, корпоративные серверы или их загрузка.
Самодостаточна: один файл, только стандартная библиотека Python, от остального репо не зависит (можно вынести).

## Требования
- **Python 3.10+** (Windows/Linux/macOS), сторонних пакетов не нужно.
- **git** в `PATH` (для замера `git clone`); без него — запуск с `--skip-git`.
- **Сеть до хостов** (обычно через корпоративный VPN):
  - `gitlab.dominigames.com:443` (HTTPS);
  - `svn.corp.dominigames.com:80` (HTTP, VisualSVN);
  - интернет `proof.ovh.net:443` — для сравнения (Cloudflare `speed.cloudflare.com` из корпоративной сети отвечает 403).
- **Креды** — в `.env` (файл `KEY=VALUE`): путь берётся из переменной окружения `PROJECT_ENV_FILE`, иначе `.env` в корне
  репо (на уровень выше папки скрипта). Нужны ключи:
  - `GITLAB_TOKEN` — personal access token GitLab с `read_repository` (для архива ветки и клона);
  - `SVN_USER`, `SVN_PASSWORD` — логин и пароль AD для SVN.
  Значения не печатаются; в выводе ошибок токен/пароль заменяются на `***`.
- **Место на диске**: до ~100–300 МБ во временной папке (`%TEMP%\net_speed_*`), удаляется в конце (в т. ч. read-only
  файлы `.git`).

## Запуск
```
python scripts/net_speed.py [--seconds 20] [--skip-git] [--skip-svn]
PROJECT_ENV_FILE=C:\path\to\.env python scripts/net_speed.py
```
`--seconds` — длительность каждого замера потока (операции `git clone` и листинг SVN — до `3 × seconds`).
Время прогона целиком — примерно `6 × seconds` плюс задержки сети.

## Что меряет (по порядку)
| Замер | Как | Что показывает |
|---|---|---|
| Задержка | DNS-резолв и TCP connect до GitLab, SVN, интернета | «длина» канала; через VPN норма — десятки мс, сотни мс — перегруженный/дальний VPN |
| Интернет | поток `https://proof.ovh.net/files/100Mb.dat` до `--seconds` с | пропускная способность канала ноутбука вне корпоративных серверов |
| GitLab поток | `GET /api/v4/projects/engine%2Fmobile/repository/archive.zip?sha=main` с токеном | скорость с GitLab (архив генерируется сервером — может упираться в сервер, не только в канал) |
| git clone | `git clone --depth 1 --branch bootstrap sa/sa-hge-autotests` (лимит `3 × seconds`) | реальная операция git: объём `.git` / время, код возврата (`timeout` — не уложился) |
| SVN поток | первый файл из листинга `data/movies/` ветки DC1, до `--seconds` с | скорость одного большого файла по HTTP |
| SVN мелкие файлы | рекурсивный листинг `data/sprites/` (до 3000 файлов / `3 × seconds`), затем скачивание в 16 потоков `--seconds` с | как ведёт себя развёртывание игры (`bootstrap_sources` качает так же): время листинга, файлов/с, Мбит/с |

Константы в начале файла (`GITLAB`, `GIT_REPO`, `GIT_ARCHIVE_PROJECT`, `GIT_ARCHIVE_REF`, `SVN_BASE`, `SVN_DIR`) — что
именно качать; при выносе в отдельную утилиту — параметризовать (аргументы/конфиг).

## Как читать результат
- Задержка до SVN/GitLab ≫ задержки до интернета → проблема в VPN/маршруте до офиса.
- Интернет быстрый, GitLab/SVN медленные при нормальной задержке → упирается в корпоративные серверы или канал офиса.
- Всё медленное, включая интернет → канал ноутбука занят (параллельные выкачки агентов, обновления) — замерять при
  паузе фоновых загрузок.
- SVN: долгий листинг при нормальной задержке → медленный сервер VisualSVN (каждый каталог — отдельный запрос).

Ориентиры (01.11.2026, ноутбук, 10 агентов качали параллельно): старый VPN — TCP 365–790 мс, GitLab 1,4 Мбит/с, SVN
листинг каталога ~13 с; новый VPN — TCP 12–136 мс, GitLab 3,3 Мбит/с, SVN 8 файлов/с (1,8 Мбит/с), интернет 7,5 Мбит/с.

## Ограничения
- SVN «поток»: если в `data/movies/` нет файлов — замер пропускается («большой файл не найден»).
- GitLab-архив на большом репо сервер может отдавать медленно сам по себе — сравнивать с `git clone`.
- Замер не отделяет нагрузку других процессов на машине — для чистой цифры остановить фоновые загрузки.
