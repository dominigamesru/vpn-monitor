# Вход логином AD: пароль — в Диспетчере учётных данных, Basic для Confluence, Jira и SVN, токен — только для GitLab

Сотрудник вводит логин и пароль AD один раз в окне; их проверяем входом в Jira, Confluence и SVN и, если хоть один
сервис принял, кладём в Диспетчер учётных данных Windows (DPAPI, привязка к пользователю Windows). Машины не в
домене, поэтому Kerberos/NTLM-вход недоступен. Пароль храним, а не меняем на токены: у VisualSVN токенов нет, а
личные токены Confluence и Jira Data Center имеют те же права, что и пользователь, — «только чтение» они не дают,
только ещё один секрет. Для GitLab пароль один раз меняется на OAuth-токен с правом `read_api` (grant type
`password`, Application ID — в настройках, `gitlab_oauth`); это единственное место, где «только чтение» обеспечено
правами, а не кодом.

## Последствия
- «Только чтение» для Confluence, Jira и SVN держится на коде (только GET), а не на правах учётки.
- Приоритет: переменная окружения → `secrets.env` → вход AD; `secrets.env` остаётся для своих токенов и отладки.
- Сменили пароль в AD — сервисы ответят 401, окно попросит войти заново. «Выйти» удаляет и пароль, и токен GitLab.
- Пароль проходит только по `127.0.0.1` (окно → API) и к самим сервисам; в лог и ответы API не попадает.
