# Постоянный путь exe и имена файлов релиза — контракт с установленными копиями

Установленный exe всегда `%LOCALAPPDATA%\DominiVPNMonitor\domini-vpn-monitor.exe`: Windows помнит «показывать иконку
в трее» по пути exe, и до 0.5.4, когда каждая версия жила в `vpn-monitor-X.Y.Z.exe`, иконка после каждого
обновления уходила под «^». Обновление скачивает новый exe рядом, переименовывает запущенный в
`domini-vpn-monitor.old.exe` (запущенный exe переименовать можно, перезаписать — нет) и кладёт новый на его место.
Обновлятель — это всегда **старая** версия кода, поэтому имена файлов в релизе — такой же контракт, как JSON: в
каждом релизе остаётся `vpn-monitor.exe` (то же exe) для обновлятелей до 0.5.4, которые знают только это имя.

## Последствия
- Версия, запущенная по старому пути (обновление от 0.5.3), копирует себя в `domini-vpn-monitor.exe`, переносит
  автозапуск и ярлык и перезапускается оттуда; CI (`upgrade_test.py`) проверяет, что новая версия работает из
  постоянного пути.
- Убрать `vpn-monitor.exe` из релизов можно, только когда все установки не старше 0.5.4.
- Папка данных WebView2 — одна `WebView2` на все версии (до 0.5.3 — своя у каждого exe); страницы отдаются с
  `Cache-Control: no-store`, чтобы кеш не показывал прошлую версию.
