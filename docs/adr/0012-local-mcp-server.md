# Локальный MCP-сервер на том же порту, что окно; только локальные клиенты

AI-агент сотрудника (Claude Code, Claude Desktop) подключается к VPN Monitor по MCP: `POST /mcp` на порту окна
(5151–5160), Streamable HTTP без SSE — ответ `application/json` на каждый запрос JSON-RPC. Отдельный порт или stdio
не нужны: приложение уже держит локальный HTTP-сервер, а агенту достаточно адреса. MCP-клиенты не шлют
`X-VPN-Monitor`, поэтому защита `/mcp` другая: `Host` — только `127.0.0.1`/`localhost`, `Origin` — нет или локальный
(страница в браузере не достучится — защита от DNS rebinding и CSRF), `Content-Type: application/json` (запрос со
страницы с таким типом требует CORS-preflight, а его сервер не разрешает). Протокол — в библиотеке (`src/mcp.rs`, тесты
`tools/list`, `tools/call`), данные — из общего состояния трея.

## Последствия
- Инструменты только читают; `vpn_check` запускает обычную проверку (те же GET к сервисам) — подтверждение не нужно.
- В ответах — те же правила, что в логе и сводке: без паролей, токенов и ссылок с ключами.
- Новые инструменты и поля только добавляются (совместимость, как у JSON API).
