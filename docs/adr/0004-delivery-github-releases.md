# Поставка через GitHub Releases, «последняя» версия — в `latest.version`

Шару заменили на GitHub Releases публичного репо `dominigamesru/vpn-monitor`: их видно без VPN, а значит, обновление
доходит и до тех, у кого VPN сломан. Каждый **релиз** — свой GitHub Release `vX.Y.Z` с exe, **настройками** этой версии и
контрольными суммами; после публикации он не меняется. Отдельный релиз с тегом `latest` хранит только файл
`latest.version` — версию, которую установленные копии считают последней. Приложение сравнивает её со своей **на
равенство**, а не «новее ли», поэтому откат — это записать в `latest.version` старую версию (workflow `promote`), без
пересборки. Настройки едут вместе с exe, поэтому exe и настройки одной версии всегда совместимы.

## Последствия
- Репо публичное — в настройках нет секретов. Креды целей лежат только на машине сотрудника (`secrets.env` в папке
  установки или переменные окружения с теми же именами, что в `.env.example`).
- Раскладка релизов (`latest/latest.version`, `vX.Y.Z/vpn-monitor.exe`, `vX.Y.Z/settings.json`) — контракт со всеми
  установленными копиями: менять только с обратной совместимостью.
- Старые версии разбирают `settings.json` новой версии **своей** схемой, когда решают, обновляться ли (v0.1–v0.3.0
  — целиком, с v0.3.1 — только блок `exe`). Поэтому в `settings.json` нельзя давать старым полям новые значения:
  в v0.3.0 `auth: "jira"` сломало обновление с 0.2.0 («unknown variant»). Новое — только новыми полями.
