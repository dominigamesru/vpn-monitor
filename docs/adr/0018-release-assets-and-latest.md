# Файлы релиза: exe с версией и платформой, «Latest» — у настоящего релиза

Заказчик 03.11: со стартовой страницы репо виден только служебный релиз «Последняя версия» (в нём `latest.version`,
без exe), а в релизе версии — два одинаковых exe (`domini-vpn-monitor.exe` и `vpn-monitor.exe`) и микрофайл
`sha256`. Хочется по best practice: версия и платформа в имени файла, лишнего нет. Копий старше 0.5.4 нет (заказчик).

Решение (0.10.0):
- exe — `domini-vpn-monitor-X.Y.Z-windows-x64.exe`; имя — в `settings.json` релиза (`exe.asset`), обновлятель 0.10.0+
  берёт его оттуда, старые имена — запасные (`update::exe_names`). Путь установки не меняется
  (`domini-vpn-monitor.exe` — идентичность иконки в трее), меняется только имя файла в релизе.
- На переходный период то же exe кладётся как `domini-vpn-monitor.exe` (бета — `-beta`): его ищут обновлятели
  0.5.4–0.9.x. Убрать, когда счётчик скачиваний этого файла в новых релизах станет нулевым.
- `vpn-monitor.exe` (обновлятели до 0.5.4) и `sha256` больше не публикуются: SHA-256 exe — в `settings.json`, GitHub
  показывает SHA-256 у каждого файла сам. Тест обновления в CI качает exe прошлого релиза по `exe.asset` или старым именам.
- «Latest» на стартовой странице — у релиза `vX.Y.Z` (стабильная; бета — пререлиз). Служебные `latest` и `beta`
  остаются (установленные копии читают `releases/download/latest/latest.version` по имени тега, а не по пометке),
  названы «Служебный: …» и без «Latest». Откат (`promote`) ставит «Latest» той версии, на которую откатили.

## Последствия
- Контракт: новое поле `settings.json` → `exe.asset`; имена файлов релиза (выше). Старые релизы не меняются.
- Ссылка «скачать последнюю» — `releases/latest` (страница релиза), прямой ссылки на файл без версии больше нет.
