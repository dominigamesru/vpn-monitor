# Заявка в поддержку создаётся через REST API Jira Service Desk под учётной записью AD сотрудника

Раньше кнопка «Создать запрос в поддержку» копировала сводку и открывала форму портала — сотрудник вставлял текст и
вручную прикладывал файлы. С 0.7.2 приложение само создаёт заявку `POST /rest/servicedeskapi/request` (Jira Service
Desk Data Center) от имени сотрудника, тем же входом AD (Basic), что уже хранится в Диспетчере учётных данных
(ADR 0006), прикладывает сводку, диагностику и лог (`attachTemporaryFile` → `request/{key}/attachment`) и открывает
заявку в браузере. Решение заказчика 2026-11-01: «в жире под пользователем создавать — и нужно».

- **Куда** — из `support_url` (`…/servicedesk/customer/portal/<id>/create/<type>`): номер портала в Service Desk — это
  id service desk, `type` — тип запроса («Общий запрос DevOps» = 23). Новых полей в `settings.json` нет; другой адрес
  (не портал) — кнопка работает по-старому: сводка в буфер и ссылка на форму.
- **Только по кнопке после просмотра:** окно показывает тему, описание, приоритет и файлы; сотрудник правит и
  нажимает «Создать заявку». Без этого приложение ничего не пишет в Jira (это действие от имени человека).
- **Приоритет** — `Low` по умолчанию; если у типа запроса нет поля приоритета (400 с `priority`), заявка уходит без него.
- **Вложения не отменяют заявку:** не приложилось — заявка создана, окно говорит, что приложить вручную.
- **Созданные заявки** — `jira-tickets.json` в папке установки (ключ, ссылка, тема, время; новые первыми, до 50) —
  список в «Настройках». Файл — контракт с установленными копиями: поля только добавляются, незнакомые терпятся.

## Последствия
- Пароль AD уходит только в Jira корпоративного адреса из `support_url` и только по HTTPS (`parse_portal` требует
  `https://`); в лог — только ключ заявки и число вложений.
- Без VPN Jira недоступна — окно показывает ошибку сети; сводку можно скопировать отдельной кнопкой.
- Смена портала или типа запроса — правкой `support_url` в удалённых настройках (ADR 0011), без релиза.
- **Дополнено в 0.8.0:** статусы запросов — `GET /rest/servicedeskapi/request/{key}` раз в 15 минут только для
  нерешённых; в `jira-tickets.json` добавлены `status`, `status_category`, `status_ms` (старые копии их терпят).
