# Спека: подсказка лучшего сервера VPN

Статус: **идея, отложено** (заказчик 2026-11-01: «сделай спеку, пока нет»).

## Зачем
У сотрудника несколько профилей или серверов VPN (Happ: msk-1, msk-2, ams…; OpenVPN — несколько .ovpn). Сейчас
приложение говорит «VPN режет скорость — переподключите», но не подсказывает, **куда**. Неделя истории уже знает, на
каком профиле у этого человека SVN быстрее и задержка ниже.

## Что видит сотрудник
- При причине «VPN» (скорость или задержка) совет становится конкретным: «На профиле **msk-2** SVN у вас обычно
  12 Мбит/с, сейчас вы на **msk-1** — 1,9. Переключитесь на msk-2».
- В «Истории» — таблица «Ваши профили VPN»: сколько часов на каждом, медиана SVN и задержки, сколько раз было плохо.
- Совет — только если по другому профилю есть ≥ 20 проверок за 7 дней и он лучше на ≥ 30% по SVN или задержке;
  иначе — прежний текст.

## Модель (чистая функция с тестами на логе заказчика)
`best_profile(records, current) -> Option<Hint>`: группировка проверок за 7 дней по (клиент, профиль), медианы
`svn_mbps` и `vpn_ms` только по проверкам, где интернет был в норме (иначе виноват интернет, а не профиль), сравнение
с текущим профилем. Данные уже пишутся в `metrics_7d.json` (клиент и профиль — с v0.4).

## Границы
- Приложение **не переключает** профиль само — только советует (переключение — в клиенте VPN, у каждого своё).
- Профили, которых нет на этой машине (давно удалены), не советуем: берём только виденные за 7 дней.
- MCP: `vpn_status` получает поле `profile_hint` — агент может сказать то же самое.
