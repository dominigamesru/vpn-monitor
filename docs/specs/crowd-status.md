# Спека: «Плохо у многих — не у вас»

Статус: **идея, отложено** (заказчик 2026-11-01: «классная идея — сохрани спеку, пока нет»). Связана с
[мониторингом для админов](admin-monitoring.md), но не требует Prometheus.

## Зачем
Когда ломается VPN-шлюз или SVN в офисе, каждый сотрудник видит «плохо» и звонит в поддержку. Если приложение знает,
что плохо сразу у многих, оно говорит: «SVN медленный у 7 сотрудников — проблема в офисе, поддержка знает» — и звонить
не нужно. Одиночная проблема (дома плохой интернет) так же остаётся видна только самому сотруднику.

## Как работает
1. Раз в 5 минут каждая копия публикует **обезличенную** строку: время, город (как в шапке), клиент и профиль VPN
   (безопасное название), статусы звеньев (норма / так себе / плохо) и сервисов офиса. Без логина, имени компьютера,
   IP и цифр, по которым можно узнать человека.
2. Копии читают сводку за последние 10 минут: сколько активных, у скольких плохо каждое звено и сервис.
3. Если плохо у ≥ 30% активных и не меньше чем у 3 человек — это **общая проблема**:
   - меню и окно: «SVN медленный у 7 из 18 сотрудников — проблема в офисе, не у вас»;
   - вывод не меняется (причина у сотрудника та же), меняется совет: «звонить не нужно, поддержка видит»;
   - уведомление — один раз в начале общей проблемы и когда она закончилась.

## Где хранить сводку (развилка для заказчика)
| Вариант | Плюсы | Минусы |
|---|---|---|
| **Маленький сервис в офисе** (`POST /report`, `GET /summary`) — рекомендую | просто, быстро, сам считает сводку | нужен хост и админ |
| Файл на общей шаре | без сервиса | доступен только в VPN; блокировки записи; Windows-права |
| Jira (комментарий в служебной заявке) | уже есть доступ | медленно, шумно, не для этого |
| GitHub (issue / gist) | уже есть CI и токены | публичное репо — нельзя; нужен приватный |

## Совместимость и приватность
- Выключено по умолчанию; адрес сервиса — в удалённых настройках (`crowd.url`), без релиза.
- Сотрудник видит в «Настройках», что отправляется (пример строки) и может выключить.
- Новые поля API — только добавляются; ADR — при реализации (протокол и хост).

## Вопросы заказчику
1. Где хранить сводку — какой вариант и какой хост?
2. Порог «общей проблемы» — 30% и минимум 3 человека подходят?
3. Можно ли показывать город, или только «в офисе / вне офиса»?
