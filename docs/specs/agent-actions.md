# Спека: AI-агент не только смотрит, но и чинит

Статус: **идея, отложено** (заказчик 2026-11-01: «сделай спеку — пока нет»). Развитие [локального MCP](ai-agent-mcp.md),
[ADR 0012](../adr/0012-local-mcp-server.md).

## Зачем
Сейчас агент на «у меня тормозит SVN» может посмотреть статус и собрать отчёт. Следующий шаг — довести до результата:
проверить, переподключить VPN, проверить снова и, если не помогло, оформить запрос в поддержку.

## Новые инструменты MCP
| Инструмент | Что делает | Подтверждение |
|---|---|---|
| `vpn_reconnect` | переподключает клиент VPN (поддерживаемые: OpenVPN Connect CLI, Happ — если есть способ) и ждёт проверку | да, в окне VPN Monitor |
| `vpn_support_request` | черновик запроса в Jira (тема, описание, файлы) → сотрудник видит его в окне и жмёт «Отправить» | да, всегда |
| `vpn_pause` | пауза проверок на N минут (созвон, презентация) | нет — безопасно и обратимо |
| `vpn_diagnose_and_fix` | сценарий: проверка → если причина VPN — предложить переподключение → проверка → итог | по шагам, как выше |

## Подтверждение человека
- Всё, что меняет состояние сети или пишет от имени сотрудника, — **только после нажатия в окне VPN Monitor**:
  инструмент возвращает агенту «ждёт подтверждения» и ссылку `http://127.0.0.1:5151/#confirm/<id>`; окно показывает,
  что и зачем просит агент; «Разрешить» / «Отклонить». Без ответа за 2 минуты — отклонено.
- Подтверждения не запоминаются «навсегда» — каждый раз (агент может ошибиться в причине).
- Лог: каждое действие агента — строкой «агент попросил … — разрешено/отклонено».

## Границы
- Переподключение — только для клиентов, у которых есть поддерживаемый способ (CLI, служба). Нет способа — агент
  получает «переподключите вручную» и инструкцию.
- Секреты агенту не отдаются никогда; запрос в Jira отправляет приложение, а не агент.
- Совместимость: инструменты только добавляются; `readOnlyHint: false` и `destructiveHint` честно проставлены.
