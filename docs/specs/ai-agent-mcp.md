# Спека: страница «AI-агент» и локальный MCP-сервер (v0.7)

Статус: **предложение, не реализовано**. Источник — запрос заказчика 2026-11-01.

## Зачем
Сотрудник работает с AI-агентом (Claude Code в VS Code, Claude Desktop). Агент должен уметь сам спросить у VPN
Monitor «что с VPN», собрать отчёт для поддержки и показать статус — без копирования из окна.

## Что делаем
1. **Страница `/agent` в окне** (вкладка «AI-агент»): для человека — как подключить приложение к своему агенту.
   - адрес API (`http://127.0.0.1:5151/api/help`) и что можно спросить;
   - готовая команда подключения MCP для Claude Code и блок настроек для Claude Desktop (копировать кнопкой);
   - что агент увидит и чего не увидит (секретов и паролей — никогда).
2. **`/mcp` — MCP-сервер** (Streamable HTTP) на том же локальном порту:
   - инструменты: `vpn_status` (вывод, маршрут, виновник, цифры звеньев), `vpn_history(range)` (сводка за час,
     сутки, неделю: инциденты, медианы), `vpn_check` (проверить сейчас и вернуть итог), `vpn_report` (отчёт для
     поддержки: сводка + диагностика + хвост лога без секретов), `vpn_diagnostics` (шаги проверки сервисов);
   - ресурсы: `vpn://status`, `vpn://report.html` — отчёт HTML с тёмной и светлой темой, чтобы агент мог показать его;
   - только `127.0.0.1`, проверка `Host`, меняющие действия (`vpn_check`) — без подтверждения не нужны: они безопасны.

## Совместимость и безопасность
- Новые адреса только добавляются; ответы — те же JSON, что `/api/state` и `/api/history` (правило совместимости).
- В ответах MCP — те же ограничения, что в логе: никаких паролей, токенов, ссылок с ключами (Happ).
- Агент на другой машине не достучится: сервер слушает только `127.0.0.1`.

## Как проверим
- Тест: ответ `tools/list` и `tools/call vpn_status` по протоколу MCP на моках.
- Вручную: `claude mcp add --transport http vpn-monitor http://127.0.0.1:5151/mcp` → «что с VPN?».
