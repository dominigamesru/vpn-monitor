# Работа с Claude в этом репо

Как ставить задачи, принимать работу и держать качество — по опыту версий 0.1–0.6 и рекомендациям Claude Code.
Правила для самого Claude — в [CLAUDE.md](../../CLAUDE.md) и `.claude/rules/`; здесь — для человека.

## Где что лежит для Claude
| Что | Где | Когда загружается |
|---|---|---|
| Главные правила | `CLAUDE.md` (меньше 200 строк) | всегда |
| Правила по темам | `.claude/rules/web.md`, `rust.md` (с `paths`) | когда трогают эти файлы |
| Процедуры | `.claude/skills/*/SKILL.md` | по описанию задачи или `/имя` |
| Термины, решения, спеки | `GLOSSARY.md`, `docs/adr/`, `docs/specs/` | по ссылке, когда нужно |
| Сценарии и состояния | `docs/ux/scenarios.md` | до любой пользовательской функции |
| Уроки | `docs/process/retro-log.md` → правила и скиллы | после нового класса ошибки |

## Постановка задачи
- **Одно сообщение — результат, а не шаги:** «пользователь видит X в ситуации Y», «релиз должен Z». Claude
  разложит на сценарии и спросит развилки с рекомендацией.
- **Крупное — через прототип:** «сделай варианты» → HTML в `docs/prototypes/` → выбор → код. Так поймали
  «маршрут как дефолт», «каскад», «медиана вместо регрессии» до кода.
- **Скриншот + одна фраза** — лучший баг-репорт; лог (`vpn-monitor.log`) — второй. Claude сам добавит строки
  в лог, если причины не видно.
- **Сообщения по ходу работы** Claude подхватывает в текущую задачу; если это новая задача — скажите
  «потом» или «в 0.7», она уйдёт в спеку.

## Приёмка
- **Что Claude сообщает после релиза:** что вышло, что проверить у себя по пунктам, что **не** проверено. Не
  проверено в настоящем хозяине (Windows, WebView2) — значит не готово, даже если CI зелёный.
- **Галерея экранов** [docs/screens.html](../screens.html) — смотреть все состояния без установки.
- **Откат за минуту:** Actions → `promote` → прошлая версия.
- **Бета для рискованного:** версия `0.7.0-beta.1` уходит только тем, кто включил «Бета» в окне.

## Контроль качества
- **Тесты на модель с реальными данными** (`route.rs`: SVN 1,3–3,4 при интернете 15 из вашего лога) — каждое
  замечание по логике превращается в тест.
- **E2E на Windows в CI** (`upgrade_test.py`): обновление с опубликованной версии, постоянный путь exe, меню в
  WebView2 «на связи» и «нарисовано». Новый класс ошибки → новая проверка здесь, а не только исправление.
- **Галерея в CI** (`screens.py --check`): интерфейс поменялся без обновления галереи — CI красный.
- **Независимое ревью** перед PR — субагент `reviewer` (файл ниже), ему дают дифф, а не выводы.

## Знания, которые копятся
- **Решения → ADR** (`docs/adr/`), когда трудно отменить: Rust, поставка, окно в браузере, вход AD. Следующие
  кандидаты: постоянный путь exe и имена файлов релиза; semver-каналы; медиана трёх проверок.
- **Фичи → сценарии и спеки:** строка в таблице состояний до кода; крупное — `docs/specs/` с вопросами в конце.
- **Ошибки → ретро → правило:** запись в `retro-log.md`, урок — в `.claude/rules/` или скилл, проверка — в CI.

## Настройки Claude Code в репо
Claude не меняет свои настройки сам — это решаете вы. `.claude/settings.json` добавлен заказчиком (2026-11-01);
субагент `reviewer` — ещё нет.

`.claude/settings.json` — меньше вопросов на безопасные команды и запрет читать `.env` с секретами (пример):
```json
{
  "permissions": {
    "allow": ["Bash(cargo test:*)", "Bash(cargo fmt:*)", "Bash(cargo clippy:*)", "Bash(cargo build:*)",
              "Bash(python scripts/screens.py:*)", "Bash(git status:*)", "Bash(git diff:*)", "Bash(git log:*)"],
    "deny": ["Read(./.env)"]
  }
}
```

`.claude/agents/reviewer.md` — независимый ревьюер (только читает):
```markdown
---
name: reviewer
description: Независимое ревью изменений перед PR — совместимость JSON и имён файлов релиза, секреты, страницы для WebView2, тесты на модель. Только читает.
tools: Read, Glob, Grep, Bash
---
Прочитай `git diff origin/main...HEAD` и проверь по CLAUDE.md и .claude/rules/: совместимость с установленными
копиями (JSON, имена файлов релиза, путь exe), секреты, страницы app/web (нет `const ipc`, textContent, обе темы),
тесты на новую логику модели, строки в docs/ux/scenarios.md и GLOSSARY.md. Ответ — «файл:строка — что — как
воспроизвести». Ничего не меняй.
```

## Проверить настройку в VS Code
- `/context` — что загрузилось и сколько стоит; `/skills` — видны ли скиллы проекта (`release`, `web-ui`,
  `ux-scenarios`); `/memory` — какие `CLAUDE.md` подхвачены.
- `/doctor prompt-audit` — устаревшие инструкции, ссылки на несуществующие файлы, противоречия (только
  предлагает правки).
- `frontend-design` — плагин из маркетплейса Claude: поставить в VS Code отдельно.
- Artifacts (публикация прототипа страницей) есть только в облачной сессии claude.ai; в VS Code прототип —
  файл `docs/prototypes/*.html`, открыть в браузере.
