# Выпуск версии

Поставка — GitHub Releases ([ADR 0004](../../../docs/adr/0004-delivery-github-releases.md)); релиз публикует CI
(`release.yml`) при новой версии в `main`. Сливает в `main` пользователь — или Claude, если пользователь явно
разрешил («выпускай», «по завершении сразу публикуй»): это разрешение — на слияние зелёного PR, не больше.

## Порядок
1. **Версия** в `app/Cargo.toml` — semver: `0.6.0` — стабильная (тег `v0.6.0`, в оба канала); `0.6.0-beta.1` —
   бета (pre-release, `domini-vpn-monitor-beta.exe`, только бета-канал). Версия, которая уже опубликована, не
   перевыпускается — только новая.
2. **Совместимость** (правило CLAUDE.md): все JSON — только новые поля с `#[serde(default)]`; новое значение старого
   поля — нельзя, в новое поле. Имена файлов в релизе — контракт с установленными копиями: старое имя
   `vpn-monitor.exe` остаётся в каждом релизе для обновлятелей до 0.5.4. Тесты `*_compatible`,
   `settings_json_readable_by_v0_2`.
3. **Интерфейс менялся** → `python scripts/screens.py` (галерея `docs/screens.html` из настоящих страниц) и
   скриншоты для README: подними `docs/screens.html` в Playwright и запусти `node .claude/skills/release/readme_shots.js`
   (пишет `docs/img/*.png`); посмотри их глазами.
4. **Заметки релиза — в `app/CHANGELOG.md`** (из него собираются баннер «Что нового», страница `#release-notes` и
   текст релиза на GitHub):
   ```markdown
   ## 0.7.1 — Ваш AI-агент знает, что с VPN        ← заголовок: польза одной фразой, с заглавной
   - **Спросите агента «что с VPN?».** Подробности…  ← для сотрудника: жирная суть + что это даёт ему
   - **Отчёт для поддержки — одной просьбой.** …     ← 2–4 пункта, без терминов из кода
   ### Технически                                    ← для разработчиков и админов: API, файлы, ADR
   - Локальный MCP-сервер `POST /mcp`…
   ```
   Пишем, что изменилось **для человека** («меню больше не скачет»), а не что поменяли в коде («toast в .bottom»).
   Без эмодзи; глаголы — как в интерфейсе; слова — из `GLOSSARY.md`.
   Текст релиза на GitHub собирает `scripts/release_notes.py` (его зовёт `release.yml`): склеивает перенесённые строки
   (GitHub показывает каждый перевод строки разрывом) и добавляет пункты невыпущенных версий после последней
   опубликованной. Посмотреть до слияния: `python scripts/release_notes.py --version X.Y.Z --prev <latest> --stdout`.
5. **Доки:** раздел версии в `app/CHANGELOG.md` (см. выше), раздел версии в `docs/app.md`, строки
   состояний в `docs/ux/scenarios.md`, новые термины в `GLOSSARY.md`, README для сотрудников — если поменялось, что
   они видят.
6. **Проверки локально:** изменился `release.yml` — вынуть шаг на Python и прогнать с `PYTHONIOENCODING=cp1252`
   (консоль раннера Windows; шаги выпуска в PR не запускаются — 0.7.1 упал на этом). `cd app && cargo fmt && cargo test`, `cargo clippy --target x86_64-pc-windows-gnu
   --all-targets -- -D warnings` (если подозрительно быстро — `touch src/main.rs` и ещё раз).
7. **PR** в `main` (шаблон — по разделам «Что было / Что исправлено / Проверка»), подписка на PR
   (`subscribe_pr_activity`), страховочная проверка через `send_later` ~50 мин.
8. **CI зелёный на текущем head** (события про старые коммиты — игнорировать, сверять `head_sha`) → слияние с
   `expectedHeadSha`. Windows-джоб включает `upgrade_test.py`: опубликованная версия сама обновляется на сборку,
   работает из `domini-vpn-monitor.exe`, страница меню в WebView2 «на связи» и «нарисована».
9. **Релиз:** ждать, пока `latest/latest.version` станет новой версией (фоновой командой с `curl`, не опросом в
   чате); проверить `sha256` релиза. Отписаться от PR, удалить страховочную проверку.
10. **Сообщить пользователю:** что вышло, что проверить у себя (по пунктам), что не проверено.

## Откат
Actions → `promote` → старая версия (и канал). Опубликованный релиз не перезаписывается и не удаляется.

## Грабли, на которые уже наступили
- **Новое имя файла в релизе ломает обновление старых копий** (0.3.0 сломал 0.2.0) — старое имя остаётся.
- **Путь exe — это идентичность иконки в трее**: exe всегда `domini-vpn-monitor.exe`, обновление — переименованием
  запущенного в `.old.exe`.
- **Проверка в браузере ≠ проверка в WebView2**: wry объявляет `window.ipc` неконфигурируемым — `const ipc` в
  странице ломает скрипт целиком (0.5.0–0.5.1). Имитация хозяина — по его исходникам; финальная проверка — CI на Windows.
- **Тег вручную не пушится** (прокси сессии) — релиз запускается версией в `main`.
- **Бета-версии не понимают копии до 0.5.4** — они ждут стабильную.
- **`release` запускается только изменением `app/**`** (или вручную, `workflow_dispatch`): правка одного workflow выпуск
  не перезапускает.
