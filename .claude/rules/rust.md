# Приложение (Rust) и поставка

- **Проверки перед пушем:** `cd app && cargo fmt && cargo test` и `cargo clippy --target x86_64-pc-windows-gnu
  --all-targets -- -D warnings` (трей, установка и WebView2 собираются только под Windows). Clippy подозрительно
  быстрый — `touch src/main.rs` и ещё раз. Версия Rust закреплена в `app/rust-toolchain.toml`.
- **Правки скриптом (python-патчи) — после `cargo fmt`:** fmt переносит строки, и якоря патча перестают совпадать.
  Каждую замену — с `assert`-проверкой, что якорь найден ровно один раз.
- **Контракт с установленными копиями** (их обновлятель — старая версия кода):
  - JSON — только новые поля; старый обновлятель разбирает `settings.json` новой версии своей схемой (v0.3.0
    сломал 0.2.0 новым значением `auth`) — тесты `settings_json_readable_by_v0_2`, `*_compatible`;
  - имена файлов в релизе: `vpn-monitor.exe` остаётся для обновлятелей до 0.5.4;
  - путь exe — идентичность иконки в трее для Windows: всегда `domini-vpn-monitor.exe`; обновление — переименовать
    запущенный в `.old.exe`, положить новый на его место;
  - `latest.version` стабильного канала — только `X.Y.Z` (копии до 0.5.4 не разбирают `-beta`).
- **Модель — чистые функции с тестами** (`route.rs`, `notify.rs`, `score.rs`); тест-кейсы — из реального лога
  заказчика (например, SVN 1,3–3,4 Мбит/с при интернете 15).
- **Сглаживание статуса — медиана трёх проверок** (регрессия по трём точкам выпад усиливает); история — как есть.
- **Лог — для диагностики у заказчика:** каждое решение, которое нельзя увидеть снаружи (откуда взят профиль VPN,
  загрузилась ли страница меню, переход на постоянный путь), — одной строкой; секретов — никогда.
- **Тег вручную не пушится** (прокси сессии): релиз запускается новой версией в `main`.
